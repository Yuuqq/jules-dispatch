The problem

Jules is powerful. One task at a time is not.

Jules runs a single task per turn. When you're migrating a framework, refactoring a monolith, or adding types across 20 modules, serial execution becomes the bottleneck.

✕ Without jules-dispatch
  • ✕Write the same prompt by hand, over and over
  • ✕Wait for one task to finish before the next starts
  • ✕No way to scale a refactor across a codebase
  • ✕AI agents can't call Jules in parallel on their own
↗ With jules-dispatch
  • ✓Describe a goal in one line; an LLM splits it into parallel tasks
  • ✓Launch 10–50 Jules sessions from a single command
  • ✓Tail logs, approve plans, message, and cancel — all in real time
  • ✓Claude and Codex treat Jules as a first-class tool

New in v1.2

Stop writing tasks by hand. Let an LLM plan them.

Give jules-dispatch one sentence and it calls your configured LLM (OpenAI / Ollama / Groq / OpenRouter) to split it into parallel Jules tasks.

bash 
jules-dispatch auto "Migrate every Express route to Fastify, and add request-validation tests for each."

It produces 6 independent tasks — auth routes, user routes, billing routes, middleware, the bootstrap file, and tests — then asks whether to dispatch them in parallel.

Supported LLM providers
OpenAI (default)
Ollama (local)
Groq
OpenRouter
Together / Fireworks / DeepInfra / Azure OpenAI / LiteLLM — any compatible endpoint
Configure via environment variables or flags. No code changes.
Get started in 4 minutes

Four steps to parallel.

01
Global install
Install once, use everywhere
bash 
npm install -g @yuuqq/jules-dispatch
02
Initialize
Connect your Jules API key
bash 
jules-dispatch init

Interactive wizard sets JULES_API_KEY. Pass --api-key for a single run.

03
Declare a task (YAML)
Version-controlled, shareable

Create a tasks/ directory and define tasks in simple YAML (multi-document --- supported):

yaml 
# tasks/migrate-to-fastify.yaml
title: "Migrate auth routes to Fastify"
repo: "your-org/your-repo"
branch: "main"
prompt: |
  Migrate every Express route under /api/auth to Fastify.
  Use the Fastify plugin system; preserve existing middleware.
  Add schema validation where appropriate.
04
Dispatch in parallel
Start your swarm
Single · batch · AI-planned
bash 
jules-dispatch dispatch tasks/migrate-to-fastify.yaml
bash 
jules-dispatch batch tasks/ --parallel 12
bash 
jules-dispatch auto "Add full TypeScript types and Vitest tests across the project"

Configure in Claude Code (example)
json 
{
  "mcpServers": {
    "jules": {
      "command": "jules-dispatch",
      "args": ["mcp"],
      "env": {
        "JULES_API_KEY": "your-jules-api-key-here",
        "LLM_API_KEY": "sk-..."   // optional, for AI planning
      }
    }
  }
}
